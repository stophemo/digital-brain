# Karpathy LLM Wiki 研究笔记

> 来源：Andrej Karpathy，*LLM Wiki*，2026-04。
> 本文是项目维护者的概括，不是原文转载；canonical URL 与许可待核实。

## 核心命题

传统 RAG 在每次查询时重新检索和拼接材料，知识不会自然积累。LLM Wiki 的替代思路
是让 Agent 持续维护一个互联的 Markdown wiki：新来源进入时就完成摘要、实体更新、
交叉引用和矛盾标记，后续查询复用已经编译的知识。

人负责选择来源、确定探索方向和判断重要性；Agent 负责重复而容易遗漏的维护工作。

## 三个语义层

- **Raw**：用户选择的外部来源，不可变，是事实证据。
- **Wiki**：Agent 生成和维护的知识页面，允许持续重组和更新。
- **Schema**：约束结构、格式、摄入、查询和健康检查的运行规则。

具体目录、工具和页面格式不是原理的一部分，应按领域和用户偏好实例化。

## 核心循环

- **Ingest**：读取一个新来源，与用户讨论重点，更新相关页面、索引和日志。
- **Query**：基于 wiki 综合回答；有长期价值的答案归档回 wiki。
- **Lint**：查找矛盾、过期论断、孤立页面、遗漏链接和新的资料缺口。

`index.md` 面向内容导航，`log.md` 面向时间记录。中等规模时，先读 index 再深入页面
可以避免过早引入复杂检索基础设施。

## 对本项目的约束

- Raw 必须保存可验证的外部快照，不能只有转换摘要或易失的外部绝对路径。
- Wiki 重构自由不能损害 provenance、可恢复性和用户数据安全。
- 链接用于表达真实关系，不能为了数量指标制造页面。
- Schema 应保持通用；实例标签和偏好属于独立配置。
- Git、Obsidian、搜索引擎和多媒体工具都是可选实现，不应写成普遍前提。
