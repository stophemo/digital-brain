## 一、目标（用户选定）

1. **开源化 / 通用化**：core 规则纯通用，采用者 clone 即用；个人特定内容（微信数据源、personal/company 领域桶、领域标签）剥离为清晰的**定制点**。
2. **精简 / 去废话**：合并重复原理、砍口语填充，让"以可执行规则为主"名副其实。

**明确不做**（用户未选）：不反过度工程——sha256 冻结、13 项 Lint、contested 矛盾机制、IPOF/工作区层、录入人工确认门**全部保留**。不为改硬而改硬。

**约束**：
- 改 `outputs/CLAUDE-schema.md`（宪法）+ 新增 `README.md`（介绍）。`Digital Brain 落地方案.md` / `workspaces.md` 本轮不动（如需同步另行提醒，不擅自改）。
- 章节编号 §1–§16 **保持不变**（落地方案 §三速查表按号引用，renumber 会引入新漂移）。
- 目录树按用户意见"**当模版**"——保留现有具体树，仅重新定性为示例结构，不抽象成占位符。

## 二、采用的方法

**宪法保持纯运行时规则；介绍与「定制点清单」移入仓库根 `README.md`。**

- CLAUDE.md 每会话加载、直接当宪法用——只放 LLM 的运行规则，不放给人看的上手介绍。
- 个人耦合点在正文中**就地通用化**（措辞改通用、示例即示例），但**不加 🔧 标记、不写"换成你的…"话术**——那些属介绍，归 README。

## 三、改动清单

### A. 开源框架（介绍 → README，宪法不含介绍）

采用者介绍与「定制点清单」放在**仓库根 `README.md`**（项目是什么、四层模型、快速开始、定制点、出处），**不进宪法**；CLAUDE.md 文首不加前言块。README 内的定制点清单：
1. §2 目录树 —— 示例结构，raw/ 子目录按数据源与领域增删。
2. §5 领域标签 —— 「领域」行占位，换成你的领域。
3. §6 录入策略表 · §7 聚合源约定 —— 数据源适配示例（微信等），不用即删。
