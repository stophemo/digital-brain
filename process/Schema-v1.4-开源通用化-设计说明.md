# Schema v1.4 设计说明 — 开源通用化 + 精简

> **状态**：📝 待实施（设计已确认，2026-07-14）
> **日期**：2026-07-14
> **影响文件**：`outputs/CLAUDE-schema.md`（宪法，v1.3 → v1.4）
> **一句话**：把 schema 从"某人的实例"打磨成一份**干净、通用、不臃肿的开源模板**——个人耦合点剥离为可替换的定制点，重复与填充语砍掉，规则语义零丢失。

---

## 一、目标（用户选定）

1. **开源化 / 通用化**：core 规则纯通用，采用者 clone 即用；个人特定内容（微信数据源、personal/company 领域桶、领域标签）剥离为清晰的**定制点**。
2. **精简 / 去废话**：合并重复原理、砍口语填充，让"以可执行规则为主"名副其实。

**明确不做**（用户未选）：不反过度工程——sha256 冻结、13 项 Lint、contested 矛盾机制、IPOF/工作区层、录入人工确认门**全部保留**。不为改硬而改硬。

**约束**：
- 只改 `outputs/CLAUDE-schema.md` 一个文件。`Digital Brain 落地方案.md` / `workspaces.md` 本轮不动（如 §2 措辞变动需同步，另行提醒，不擅自改）。
- 章节编号 §1–§16 **保持不变**（落地方案 §三速查表按号引用，renumber 会引入新漂移）。
- 目录树按用户意见"**当模版**"——保留现有具体树，仅重新定性为示例结构，不抽象成占位符。

---

## 二、采用的方法

**core 纯通用 + 文首「定制点清单」+ 就地 🔧 标记。**

- 不搬移内容（伤可读性），而是让正文规则读起来完全通用，把"要改的几处"在开头列成 checklist，正文对应处打 `🔧`。
- 比"重结构/分文件"轻——保持**单文件宪法**（每会话加载一份，符合原设计）。
- 比"纯就地标记"清晰——采用者开头即知总共只有 4 处要动，不必通读 16 节找齐。
- 版本 v1.3 → **v1.4**。

---

## 三、改动清单

### A. 开源框架（新增·前言块）

标题引言块之后、§1 之前，插入**无编号前言**：

```
## 🔧 采用者定制点（开源模板 → 你的实例）
本 Schema 通用规则照用；仅以下几处按你的领域替换，正文对应处标 🔧：
1. §2 目录树 —— 示例结构。raw/ 子目录（wechat/personal/company…）按你的数据源与领域增删。
2. §5 领域标签 —— 「领域」行占位，换成你自己的工作/专业/兴趣领域。
3. §6 录入策略表 · §7 聚合源约定 —— 标 🔧 的是数据源适配片段（如微信），不用的删掉。
其余（权限模型、SOP、frontmatter、Lint、安全、工作区）无需改动。
```

### B. 通用化改动（逐点）

| 位置 | 现状（个人耦合） | 改为 |
|------|----------------|------|
| §2 目录树 | 树被当"标准结构"；第 62 行「raw/ 结构固定」 | 树上方加一行「以下为**示例结构**（含可选数据源），照抄后按领域增删」；`wechat/personal/company` 定性为示例桶；「结构固定」→「raw/ 的**分类原则**固定（按数据源安全边界/摄取管线分类），**具体子目录按需增删**」 |
| §5 领域标签 | 已有占位+脚注 | 保留；措辞收紧，给 🔧 |
| §6 录入策略表 | `.txt（微信导出）` 行是特定源 | 表整体已是通用「格式→能力」；`微信导出` 行标 🔧「示例适配器，非本源可删」 |
| §7 persona 约定 | 「群聊是数据源、不是实体」是聊天特定 | 上提为通用原则：「**聚合型数据源**（群聊/论坛/邮件列表/合集）是数据源不是实体，从中提取信号路由到实体页」，🔧 举例微信群 |
| §15 安全 | `raw/（含 wechat/company/personal）` | → `raw/（含敏感来源）` |

### C. 精简 / 去废话（逐点·中等力度）

**消重**（同一规则讲多遍 → 讲一次 + 引用）：
- 工作区"vault 外=天然隔离"原理：现散在 §1、§2(第64行)、§16(第509行) → 完整版只留 §16，§1/§2 一句话带过（"见 §16"）。
- raw 附件镜像规则：现 §2、§6③、§14#13 各一遍 → 完整规则留 §2，§6③/§14#13 改一行引用。
- "raw 摄取后冻结/唯一编辑窗口"：§1、§6④、§7 → 完整版留 §6④，§1/§7 精简为一句。

**去 rationale 散文 / 填充语**（文首自称"理据用引用块"，实际大量内联散文）：
- §13、§16 开头的散文式论证 → 规则句保留，理据压进 `>` 引用块或删。
- 砍口语填充：§7「以上仅为推荐——wiki 完全由你维护，你觉得哪种组织方式更适合当前知识结构就怎么来」→「结构建议，非强制；可按知识实际重组」；§16「工作区是'活的'目录——人和你共同在里面干活、迭代、产出成品」重复描述收敛。

预计 535 行 → 约 **430–460 行**，仅删重复与水词，规则语义不丢。

### D. 明确不动（范围边界）

sha256 / 13 项 Lint / contested / IPOF·工作区 / 录入确认门 / 章节编号 / frontmatter 字段 / log·index 格式约定——全部保留。

## 四、验证标准

- **通用化**：全文搜索无未标记的 `微信`/`wechat`/`company`/`personal` 作为**强制规则**出现（只允许出现在 §2 示例树、🔧 适配片段、或明确的"示例"语境）。
- **精简**："vault 外=隔离"原理与"raw 附件镜像"规则各自在全文只出现**一次完整版**，余处为引用。
- **零语义丢失**：改动前后逐节比对，D 清单项一字不动；B/C 只改定性/措辞/位置，不删任何一条可执行规则。
- **行数**：落在 430–460 区间（偏离则复核是否误删规则或漏砍水词）。
